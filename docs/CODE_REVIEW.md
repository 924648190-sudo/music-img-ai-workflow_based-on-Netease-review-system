# 3.1 代码审查与 Fork 环境模拟

日期：2026-10-18。对象为发布源码目录，不是上级私人项目目录。未推送 GitHub、未操作线上 Dify、未调用真实模型或应用 API。

## 审查结论

当前发布副本未发现维护者 API Key、授权 Cookie、应用密钥、私有模型网关或已配置的个人凭据引用。77 节点、104 条连接均保留；环境变量和会话变量列表为空；28 个 HTTP 节点均使用无鉴权公开接口；10 个 LLM 节点只有供应商/模型选择，没有绑定维护者的 credential ID。

调用脚本在运行时读取使用者进程环境或本地 `.env` 中的 `DIFY_API_KEY`，没有维护者密钥兜底。缺少密钥时在构造请求阶段终止；鉴权只放在 HTTPS 请求头，不写入正文、日志或源码，并禁止自动重定向。

## 发现与处理

1. **P2，已修复：大写或未加引号的环境密钥赋值存在漏检。** 检查器现在识别有供应商前缀的环境变量名，以及未加引号的赋值，并测试空值示例不会误报。
2. **P2，已修复：仅扫描工作目录不足以发现 Git 已跟踪的敏感文件。** 检查器现在检查 Git 索引，包含磁盘已删除但仍被跟踪的 `.env`，以及工作文件已清理、暂存区仍含密钥的情形。
3. **P2，已修复：符号链接可能引入发布目录外的私人文件。** 检查器拒绝未审阅的符号链接，包括断开的链接。

当前没有发现因代码内凭据而导致 fork 使用维护者额度的未解决问题。模型与插件在新工作区中的可用性仍需使用者确认，详见 `MODEL_REQUIREMENTS.md`。这些部署前提不等于携带了维护者凭据。

## 模拟方法

`scripts/simulate_fork.py` 在临时目录中执行实际 Git 初始化、提交和本地克隆。子进程环境不继承运行者的 API Key。源仓库放入随机、虚构的本地 `.env` 密钥作为检测标记，确认它被忽略，并逐一检查该临时仓库所有 Git 对象中不含此标记。

随后在克隆目录比较全部跟踪文件，校验 DSL/JSON 等价性，重建工作流，比较重建前后完整结构，并执行回归测试与隐私检查。API 调用部分通过替身模拟，socket 连接被阻止；没有消耗真实额度。

| 场景 | 验证结果 |
|---|---|
| 获取源码 | 跟踪文件与模拟源仓库逐文件一致 |
| 本地 `.env` | 不进入 Git 对象，也不出现在克隆中 |
| 工作流重建 | 完整结构与原定义一致，77 节点 / 104 边 |
| 不提供密钥 | 退出码 1；请求次数 0；真实网络尝试 0 |
| 提供使用者模拟密钥 | 仅使用该密钥及使用者指定地址；1 次模拟请求；真实网络尝试 0 |
| 测试 | 原工作流 12 项 + 发布检查 11 项通过 |
| 发布源码扫描 | 零命中 |
| 原私人存档补充检查 | 205 个文本文件的常见密钥模式零命中；私人存档仍不应上传 |

## 结论适用范围

可以分享完整工作流，让使用者在自己的 Dify 工作区配置自己的模型凭据/额度后使用；源码本身不提供维护者的调用资格。Dify 应用 API Key 属于特定应用，模型费用归属由执行工作区的供应商凭据或额度决定。[Dify API 文档](https://docs.dify.ai/en/api-reference/guides/get-started)、[模型供应商文档](https://docs.dify.ai/en/cloud/use-dify/workspace/model-providers)

本次为本地 Git clone 和离线/模拟测试，不是 GitHub 远程 fork，也未验证另一套全新 Dify 的真实导入和模型调用。没有现有 Git 仓库历史可供审查；临时模拟仓库的对象检查不能代替未来实际远程仓库的历史扫描。源码模式扫描不能证明所有未知格式的敏感信息均不存在。

只将发布目录作为仓库根目录。若另行公开维护者 Dify 应用的在线入口，其访问费用与源码 fork 隔离是两个问题，不在本次模拟结论范围内。
