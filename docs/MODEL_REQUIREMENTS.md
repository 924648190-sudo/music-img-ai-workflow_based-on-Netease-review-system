# Fork 后的模型配置

发布包包含完整工作流定义、代码节点、提示词和构建所需基线，没有携带维护者工作区的模型凭据。

| 节点 | 当前模型名 | 能力要求 |
|---|---|---|
| 115、241、250、267、287 | `deepseek-v4-flash` | 文本推理与 JSON 输出 |
| 200、215、220 | `deepseek-flash` | 文本分析与结构化输出 |
| 134、176 | `deepseek-flash` | 图像输入、视觉审阅及结构化输出 |

供应商标识为 `langgenius/deepseek/deepseek`；DSL 固定了公开插件版本标识。名称与能力来自当前项目配置，不代表在任意 Dify 安装中都默认可用。

使用者需在自己的工作区安装兼容插件、配置自己的模型供应商凭据或可用额度，并确认这些模型实际可调用。若所选插件/模型不可用，须在对应 LLM 节点改选自己可用的模型；两个视觉节点必须选择支持图像输入的模型。不能只填写应用 `DIFY_API_KEY` 就省略模型配置。

本次仅验证工作流文件完整性、离线执行逻辑和凭据隔离；没有在另一套全新 Dify 上完成真实导入及模型调用，因此不能把本地通过视为所有 Dify 环境均可直接运行。两个 RAG 当前未接入，无需额外取得私人知识库才能还原当前 77 节点工作流。

费用归属取决于执行工作区的模型供应商凭据或额度，而不是 DSL 作者。应在使用者自己的工作区运行；导入到维护者工作区并使用其已有模型配置，则仍可能消耗维护者额度。[Dify 模型供应商说明](https://docs.dify.ai/en/cloud/use-dify/workspace/model-providers)
